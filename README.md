# Supplier Search Assistant

> **Work in progress.** This is the final project for a Generative AI bootcamp.

A Text-to-SQL assistant for procurement questions. A buyer asks in plain language,
for example *"Which active suppliers sold us safety gloves last year, and at what average
price in EUR?"*. An LLM pipeline then:

1. runs a cheap intake step with structured output (Pydantic) to understand the request,
2. runs a tool-calling agent (Strands Agents) that writes **read-only** SQL against SQLite,
3. corrects its own queries from error messages and asks for clarification when the question is ambiguous,
4. explains the result in plain language.

FastAPI, Streamlit and Docker come in later phases.

## The data is fully synthetic

`data/suppliers.db` is generated by `scripts/build_db.py`. All supplier names, prices,
contracts and carts are invented. No real company data is used. The generator is
deterministic: the same seed produces the same data on every machine.
The tables, views and quirks are described in [docs/data_model.md](docs/data_model.md).

## Setup

You need [uv](https://docs.astral.sh/uv/). It installs Python 3.12 (pinned in `.python-version`) for you.

```bash
uv sync                  # creates .venv and installs the dev dependencies (pytest)
cp .env.example .env     # optional; nothing in this phase needs an API key
```

## Rebuild the database

```bash
uv run python scripts/build_db.py            # seed 42 -> data/suppliers.db
uv run python scripts/build_db.py --seed 7 --out /tmp/suppliers_seed7.db
```

The output file is **deleted and rebuilt**, so only point `--out` at `data/` or a temp directory.

## Run the tests

```bash
uv run pytest -q
```

The tests build a fresh database in a temp directory. They check the schema, integrity,
the data properties the agent depends on, reproducibility across runs, and that the
read-only connection (`assistant.db.get_readonly_connection`) rejects writes.

## Development workflow

Work happens on the `dev` branch. When an iteration is finished and green, open a pull
request from `dev` to `main` and merge it with a merge commit. `main` is protected.

Install the git hooks once per clone:

```bash
uv run pre-commit install
```

| When | What runs |
|---|---|
| `git commit` | File hygiene, secret scan (gitleaks), Ruff lint and format, a block on committing to `main`, and Terraform and Dockerfile linters once such files exist |
| `git push` | The same checks, plus the test suite |
| Pull request (GitHub Actions) | Ruff, gitleaks, Terraform and Hadolint (when present), and the tests on Python 3.10 and 3.12 |

If a hook reformats a file, the commit stops once: run `git add -u` and commit again.
To run every check by hand: `uv run pre-commit run --all-files`.

## Layout

```
scripts/build_db.py      synthetic data generator (standard library only)
data/suppliers.db        generated database (committed)
src/assistant/db.py      read-only SQLite access
tests/                   pytest suite
docs/data_model.md       tables, views and quirks
```
